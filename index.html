01关于我

我把自己看成一个系统构建者。面对复杂问题，我通常会从目标、状态、边界和失败恢复开始拆解， 再把它做成能被真实使用、观察和继续演进的系统。Agent 对我吸引力正在这里： 它不只是一次问答，而是一段需要被调度、被记住、被恢复的工作。

我长期在做的，是让 Agent 从一次性的调用变成能够持续工作的系统：围绕运行时、任务调度、 工具与工作空间，处理状态连续性、资源边界、失败恢复和可观测性。这些是我在不同工程环境里 反复思考的问题，也会沉淀到个人项目中。

在这条主线之前，我有多年的云原生后端开发经验，长期使用 Spring 全家桶构建微服务与分布式系统， 也持续处理高并发、容灾、消息、缓存和数据一致性等工程问题。这些经历构成了我今天做 Agent Infrastructure 的技术底座：先把系统做稳，再让能力变得聪明。

业余时间会写一些关于 Agentic 编程工具、上下文工程的技术笔记， 也在持续维护开源的 Z_Agent ↗。 这是一个面向目标驱动执行的 Agentic Workbench，将 Agent Runtime、Goal / Run / Task、 Canvas、HITL、上下文压缩、长期记忆与 Workspace 组合起来，重点探索复杂任务的可恢复执行、 上下文连续性与人机协作。

02我在构建

  1. Agent Runtime

    让 Agent 能持续工作

    状态 · 调度 · 工具 · 事件

    • 关注 Agent 的会话、任务、工具调用和后台执行生命周期，让一次运行能够被观察、暂停和继续。
    • 用事件驱动、队列、背压和幂等机制处理长程任务中的调度、唤醒与状态流转。
    • 把可靠性、可观测性和资源边界放进运行时，而不是留给业务侧自行兜底。
    Runtime · Event-driven · Scheduling · Observability
  2. Long-horizon Work

    让复杂任务可以恢复

    上下文 · 记忆 · 恢复 · 人机协作

    • 把上下文压缩、历史证据和结构化状态视为运行时的一部分，尽量让信息不会因为长对话而丢失。
    • 设计记忆、Workspace 和文件能力的边界，让 Agent 在需要时取回信息，同时保持数据可控。
    • 把人工确认、中断、失败和重启当作正常路径，持续探索更自然的人机协作方式。
    Context · Memory · Workspace · HITL
  3. Systems Thinking

    把实践沉淀成自己的工具

    开源项目 · 个人工作台 · 持续迭代

    • 用个人项目验证对 Agent Runtime、长期记忆、上下文工程和多 Agent 协作的理解。
    • 把日常思考、脚本、知识和实验组织成可以被 Agent 使用的数字工作空间。
    • 偏好小步迭代、真实运行和留下证据，让系统随着使用逐渐长出自己的形状。
    Open Source · Personal Systems · Continuous Learning
